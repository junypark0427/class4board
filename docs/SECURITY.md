# 보안과 익명성

## 경계

학생 → 같은 출처의 Next.js `/api/posts` → 서버 전용 키로 `submit_post` 호출 → 기본 비공개 `posts` 저장.
4반 한마디 → `/api/board`로 익명 제출 → 서버 전용 키가 `submit_class_message` 호출 → 관리자 승인 전 비공개.
공개 게시판 → publishable key의 `anon` 역할 → RLS가 승인·비숨김 `class_messages`만 조회 허용.
관리자 → Supabase Auth 이메일/비밀번호 로그인 → 본인의 JWT와 공개 키 → RLS/`moderate_post`로 권한 확인.
결과 확인 → `/api/result`에 번호를 POST → 서버에서 SHA-256 해시 → `lookup_result`가 상태·답변·수정 시각만 반환.

`lib/server.ts`는 `server-only`로 클라이언트 번들 유입을 차단합니다. 관리자 UI를 우회하더라도 DB의 RLS와 함수 내 allowlist 검사가 적용됩니다. 일반 authenticated 계정은 관리자 권한이 없습니다. 클라이언트에 보이는 publishable key는 비밀 키가 아닙니다.

`/admin` 경로는 로그인 폼을 보여주기 위해 누구나 열 수 있지만 인증 전에는 의견 조회를 시작하지 않습니다. 실제 데이터 경계는 화면 표시 여부가 아니라 PostgreSQL 권한과 RLS입니다. `anon`에는 관리자 테이블의 SELECT 권한이 없고, `authenticated`에는 SELECT 권한만 주되 `admin_members`에 등록된 UID만 정책을 통과합니다. 직접 INSERT/UPDATE/DELETE 권한은 어느 브라우저 역할에도 없습니다.

## 테이블

| 테이블 | 저장 정보 | 앱에서 접근 가능한 사용자 |
|---|---|---|
| public.posts | 의견, 전달/결과 희망, 처리 상태, 공개 여부, 숨김, 내부 메모, 작성자 답변, 버전 | 관리자만 읽기, 관리 함수만 변경 |
| public.published_posts | 이전 버전의 건의함 공개 사본(데이터 보존) | 익명 읽기 권한 제거, 학생에게 비공개 |
| public.class_messages | 4반 한마디 내용·승인/숨김 상태·시각 | 승인·비숨김 행만 익명 읽기, 전체는 관리자 읽기 |
| public.class_message_actions | 한마디 승인·취소·숨김 작업자와 시간 | 관리자만 읽기 |
| public.admin_members | 관리자 UUID와 역할 표시 이름 | 관리자만 읽기, SQL 소유자만 등록 |
| public.admin_actions | 담당자 UUID/표시 이름, 시간, 변경 종류/상태 | 관리자만 읽기, 관리 함수만 추가 |
| private.receipts | 확인번호 SHA-256 해시와 글 UUID | 직접 학생/관리자 접근 불가 |
| private.submission_limits | 임시 쿠키 해시별 제한과 전체 제한 | 직접 학생/관리자 접근 불가 |

학생 이름·이메일·IP·기기 지문·위치·User-Agent를 읽거나 저장하는 코드가 없습니다. 학생을 Supabase Auth에 익명 가입시키지도 않습니다. 글과 쿠키 해시는 서로 연결하지 않습니다. 확인번호 원문은 DB에 저장하지 않으며 학생에게 한 번만 전달합니다. 번호는 32 random bytes (256 bits)입니다.

## 제한과 보관

- 제목 2~80자, 본문 5~2,000자, 메모 4,000자, 답변 2,000자. 프론트/서버/DB에서 검사합니다. JS는 UTF-16 길이를 사용하므로 일부 이모지는 DB보다 보수적으로 제한됩니다.
- 4반 한마디 본문은 2~500자이며 제목·카테고리·학생 번호 입력란이 없습니다. JSON 본문은 4,000바이트에서 중단합니다.
- JSON 제출 요청은 스트림을 읽으며 16,000바이트에서 중단합니다. 확인번호 요청은 512바이트로 제한합니다.
- 같은 출처 POST, honeypot, 서명된 httpOnly/SameSite=Strict 쿠키와 DB 트랜잭션으로 60초 쿨다운을 적용합니다. 전체 건의함은 첫 제출을 기준으로 1시간에 100건으로 제한합니다.
- 쿠키를 지우거나 새 브라우저를 쓰면 개별 제한을 우회할 수 있습니다. 첫 쿠키를 받기 전 동시에 제출하는 요청에도 같은 한계가 있습니다. 전체 제한은 유지되지만 악의적인 사용자가 이를 소진할 수 있습니다. IP 수집 없이 운영하는 기본적인 도배 완화 기능이며 DDoS 방어는 아닙니다.
- 확인번호 추측은 256-bit 난수로 어렵게 했지만 결과 조회 자체의 분산 트래픽 제한은 구현하지 않았습니다. 필요시 호스팅 방화벽 정책을 추가하고 그 서비스의 접속정보 수집 범위를 별도 확인하세요.
- 만료된 도배 제한 레코드는 다음 성공 가능한 제출 트랜잭션에서 정리합니다. 제출이 없으면 남아 있을 수 있습니다. 운영자가 필요시 `delete from private.submission_limits where expires_at <= now();`를 예약 실행할 수 있습니다.
- 의견·확인번호 해시·관리 기록에는 자동 만료가 없습니다. 학기/학년 말 보관 기간을 정한 뒤 Supabase 관리자가 불필요한 의견을 삭제하세요. 의견 삭제 시 관련 확인번호·관리 기록도 삭제됩니다. 백업에는 제공업체 보관 정책이 적용됩니다.
- 관리자 계정 정보는 Supabase Auth가 저장합니다. 관리자 세션은 탭의 sessionStorage를 사용하지만 브라우저의 세션 복원 기능이 있을 수 있으므로 반드시 로그아웃하세요. 관리자 해제는 `admin_members`에서 UID를 삭제하면 즉시 DB 권한에 반영됩니다.
- 앱에 분석·광고 추적, 요청 본문/비밀번호/토큰 로그는 없습니다. 호스팅 업체와 Supabase가 별도 운영 로그/IP를 기록할 수 있어 완전한 익명성은 보장하지 않습니다.

## 렌더링과 기록

글·메모·답변은 React의 일반 텍스트로만 렌더링합니다. HTML 입력이나 `dangerouslySetInnerHTML`을 쓰지 않습니다. 승인된 한마디만 공개 게시판에서 읽을 수 있고 관리자 데이터는 서버 HTML에 포함되지 않습니다. 조회 응답은 `no-store`입니다. 관리자 변경은 버전 검사와 행 잠금으로 충돌을 감지하고 작업 기록과 같은 트랜잭션으로 저장합니다.

## 건의함 비공개와 별도 공개 게시판

원본 `posts`에는 `anon` SELECT 권한이 없습니다. 이전 버전의 `published_posts`에는 과거 공개 사본이 남아 있어도 003 마이그레이션이 익명 SELECT 권한과 정책을 제거합니다. 관리 UI는 건의함의 새로운 공개 승인을 제공하지 않습니다.

`class_messages`는 별도 테이블입니다. 기본 상태 `pending`은 익명 조회에서 제외되고, `moderate_class_message`가 관리자 UID를 확인한 뒤 승인한 행만 RLS가 보여줍니다. 거절·공개 취소·숨김은 익명 읽기에서 즉시 제외됩니다. 변경자는 `class_message_actions`에 남습니다.
